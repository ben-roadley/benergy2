# Learning Angular (exercise-catalog-ui)

## 1. Scaffolding: standalone app, PrimeNG, dark mode

- 🧠 **Key concept:** `ng new` generates a standalone, zoneless app. There is no `NgModule`: `main.ts` calls `bootstrapApplication(App, appConfig)` and `app.config.ts` lists the global providers (`provideRouter`, `providePrimeNG`). Components declare what they use in their own `imports: [...]` (here `ButtonModule`, `CardModule`). State lives in `signal()`s read as `clicks()` in the template.
- 🖼️ **Vue connection:** `app.config.ts` ≈ the `app.use(router).use(PrimeVue, {...})` chain in `main.ts`. A component's `imports` array replaces Vue's auto-registered local components in `<script setup>`. `signal` ≈ `ref`, but you call it (`clicks()`) to read and use `.set()` / `.update()` to write.
- 🔍 **Under the hood:** Dark mode is a CSS class: `darkModeSelector: '.app-dark'` tells the Aura preset to emit its dark tokens under `.app-dark`, and `<html class="app-dark">` turns it on permanently. Zoneless means change detection is triggered by signals and events, not by patching the browser with zone.js. In Docker, `ng serve --host 0.0.0.0 --poll 1000` is needed so the dev server is reachable and sees bind-mount changes on Windows.
- 🛠️ **Common pitfalls:** forgetting to add a PrimeNG module to the component's `imports` (the tag silently renders as an unknown element or errors); mutating a signal's object value in place instead of `set`/`update`; the anonymous `node_modules` volume in compose hides host `node_modules`, so after `package.json` changes rebuild the image (`docker compose build exercise-catalog-ui`).

## 2. Home page: service, `rxResource`, routing, dev proxy

- 🧠 **Key concept:** `MuscleService` wraps `HttpClient` (`provideHttpClient()` in `app.config.ts`) and returns an `Observable`. `Home` hands it to `rxResource({ stream })`, which exposes signals `value()`, `isLoading()` and `error()`: the template just branches on them with `@if / @else if`, and `@for` renders the cards. Each card is wrapped in `<a [routerLink]="['/muscles', muscle.name]">`, and the router URL-encodes the name (`middle%20back`).
- 🖼️ **Vue connection:** `rxResource` ≈ a composable like `useFetch` returning `{ data, pending, error }` refs. `routes` ≈ the `routes` array of Vue Router, and `<router-outlet />` ≈ `<router-view />`. `providers` in `app.config.ts` is Angular's equivalent of `app.use(...)`, and `inject()` is like `useX()` for services.
- 🔍 **Under the hood:** services are classes created by dependency injection; `providedIn: 'root'` makes one shared instance. The browser calls `/api/muscles` on the dev server (port 4200), which proxies to `http://exercise-catalog-api:8090/muscles` (`proxy.conf.json`, enabled in `angular.json` under `serve.options.proxyConfig`). Same origin, so no CORS. The proxy runs inside the container, hence the Docker service name as the target.
- 🛠️ **Common pitfalls:** `angular.json` / `proxy.conf.json` are only read at startup: restart the dev server after changing them. Forgetting `provideHttpClient()` gives a `NullInjectorError` for `HttpClient`. In tests, replace the service (`{ provide: MuscleService, useValue: ... }`) instead of hitting the network. Navigating to `/muscles/:name` logs "Cannot match any routes" until that page exists.
