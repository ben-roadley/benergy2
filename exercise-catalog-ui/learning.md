# Learning Angular (exercise-catalog-ui)

## 1. Scaffolding: standalone app, PrimeNG, dark mode

- 🧠 **Key concept:** `ng new` generates a standalone, zoneless app. There is no `NgModule`: `main.ts` calls `bootstrapApplication(App, appConfig)` and `app.config.ts` lists the global providers (`provideRouter`, `providePrimeNG`). Components declare what they use in their own `imports: [...]` (here `ButtonModule`, `CardModule`). State lives in `signal()`s read as `clicks()` in the template.
- 🖼️ **Vue connection:** `app.config.ts` ≈ the `app.use(router).use(PrimeVue, {...})` chain in `main.ts`. A component's `imports` array replaces Vue's auto-registered local components in `<script setup>`. `signal` ≈ `ref`, but you call it (`clicks()`) to read and use `.set()` / `.update()` to write.
- 🔍 **Under the hood:** Dark mode is a CSS class: `darkModeSelector: '.app-dark'` tells the Aura preset to emit its dark tokens under `.app-dark`, and `<html class="app-dark">` turns it on permanently. Zoneless means change detection is triggered by signals and events, not by patching the browser with zone.js. In Docker, `ng serve --host 0.0.0.0 --poll 1000` is needed so the dev server is reachable and sees bind-mount changes on Windows.
- 🛠️ **Common pitfalls:** forgetting to add a PrimeNG module to the component's `imports` (the tag silently renders as an unknown element or errors); mutating a signal's object value in place instead of `set`/`update`; the anonymous `node_modules` volume in compose hides host `node_modules`, so after `package.json` changes rebuild the image (`docker compose build exercise-catalog-ui`).

## 2. Home page: service, `rxResource`, routing, dev proxy

- 🧠 **Key concept:** `MuscleService` wraps `HttpClient` (`provideHttpClient()` in `app.config.ts`) and returns an `Observable`. `Home` hands it to `rxResource({ stream })`, which exposes signals `value()`, `isLoading()` and `error()`: the template just branches on them with `@if / @else if`, and `@for` renders the cards. Each card is wrapped in `<a [routerLink]="['/muscles', muscle.name]">`, and the router URL-encodes the name (`middle%20back`).
- 🖼️ **Vue connection:** `rxResource` ≈ a composable like `useFetch` returning `{ data, pending, error }` refs. `routes` ≈ the `routes` array of Vue Router, and `<router-outlet />` ≈ `<router-view />`. `providers` in `app.config.ts` is Angular's equivalent of `app.use(...)`, and `inject()` is like `useX()` for services.
- 🔍 **Under the hood:** services are classes created by dependency injection; `providedIn: 'root'` makes one shared instance. The browser calls `/api/muscles` on the dev server (port 4200), which proxies to `http://exercise-catalog-api:8090/muscles` (`proxy.conf.json`, enabled in `angular.json` under `serve.options.proxyConfig`). Same origin, so no CORS. The proxy runs inside the container, hence the Docker service name as the target.
- 🛠️ **Common pitfalls:** `angular.json` / `proxy.conf.json` are only read at startup: restart the dev server after changing them. Forgetting `provideHttpClient()` gives a `NullInjectorError` for `HttpClient`. In tests, replace the service (`{ provide: MuscleService, useValue: ... }`) instead of hitting the network. Navigating to `/muscles/:name` logs "Cannot match any routes" until that page exists.

## 3. Muscle exercises page: route params, DataView, client-side filter

- 🧠 **Key concept:** the route `muscles/:name` renders `MuscleExercises`. With `withComponentInputBinding()` in `provideRouter`, the `:name` param arrives as a signal input (`name = input.required<string>()`). `rxResource` takes `params: () => this.name()`, so it refetches by itself if the param changes. The search box is a `signal` and the filtered list is a `computed` over the resource value and the query. `p-dataview` gives the list template and the paginator.
- 🖼️ **Vue connection:** `input()` bound from the route ≈ `props: true` in Vue Router. `computed` is the same idea as Vue's `computed`, but it is a function you call (`filtered()`). `rxResource` with `params` ≈ `watch` + fetch, or a `useFetch` with a reactive URL.
- 🔍 **Under the hood:** the list is filtered in the browser (max about 150 rows), so typing needs no request. An `effect` puts the paginator back on page 1 when the query changes. Failed thumbnails are tracked in a signal holding a new `Set` each time (signals compare by reference, so mutating the old set would not notify). Image URLs come from one constant, `IMAGE_BASE_URL`, so moving the images later is a one-line change.
- 🛠️ **Common pitfalls:** forgetting `withComponentInputBinding()` makes `input.required` throw (the param is never bound). PrimeNG renders inside its own components, so scoped CSS does not reach the `<img>` of `p-image`: use `:host ::ng-deep` sparingly or the `imageClass` input. `p-dataview` shows its paginator even for one page unless `[alwaysShowPaginator]="false"`. PrimeNG 22 shows an "Invalid PrimeUI License" toast in this dev setup: it does not affect the app.

## 4. Exercise page: `@if ... as`, `@empty`, 404 handling

- 🧠 **Key concept:** the route `exercises/:slug` is bound to `slug = input.required<string>()` like the muscle page. The template uses `@else if (exercise.value(); as e)` to name the loaded value once, `@for ... @empty` for empty arrays (images, muscles) and `<dl>` for label / value pairs. `null` fields get a muted "Not specified" with a plain `@if / @else`.
- 🖼️ **Vue connection:** `@for ... @empty` ≈ `v-for` plus a `v-if="!items.length"` sibling. `@if (x; as e)` ≈ `v-if="x"` with a `v-slot`-like alias. Breadcrumb items are built in a `computed` from the loaded data.
- 🔍 **Under the hood:** `rxResource` stores the thrown `HttpErrorResponse` in `error()`. A `computed` checks `error instanceof HttpErrorResponse && error.status === 404` to show "not found" instead of a generic error. The slug goes through `encodeURIComponent` when building the URL.
- 🛠️ **Common pitfalls:** PrimeNG's breadcrumb renders an `<ol>`, so a test selector like `ol li` also matches breadcrumb items: scope selectors to your own element. `p-image` with `[preview]="true"` adds a zoom button and a modal; the thumbnail size is set through `imageClass`, not on `p-image` itself. Use `minmax(min(18rem, 100%), 1fr)` in grids to avoid horizontal overflow on very narrow screens.

## 5. Filters: `p-select`, `FormsModule` and derived options

- 🧠 **Key concept:** three `p-select` (category, level, equipment) sit next to the search box. Each filter is a `signal<string | null>`; the options are `computed` signals built from the loaded exercises (distinct, sorted, non-null); `filtered` is one `computed` that applies the search and the three filters with AND. `null` means "no filter" (the clear button resets it).
- 🖼️ **Vue connection:** this is a `v-model` on a select, but Angular's `[(ngModel)]` is a two-way binding of a plain value. With signals we split it: `[ngModel]="category()"` and `(ngModelChange)="category.set($event)"`. `computed` options ≈ Vue `computed`.
- 🔍 **Under the hood:** `p-select` is a form control, so it implements `ControlValueAccessor` and needs `FormsModule` in the component `imports` to work with `ngModel`. Everything stays client-side: one request, then pure signal recalculation. The paginator `effect` reads all filter signals, so any change sends the list back to page 1.
- 🛠️ **Common pitfalls:** forgetting `FormsModule` gives a "Can't bind to 'ngModel'" error. Options derived from the *filtered* list would shrink as you filter; derive them from the full list. Exercises with `equipment: null` cannot be selected by the equipment filter (spec: out of scope).
